## 5. Migrate — one real abort, fixed

```
MIGRATE_ALLOW_DB=uat_0912 DATABASE_URL=postgresql://jtj60@127.0.0.1:5544/uat_0912 \
  pnpm --filter @dorado/api migrate
```

Genesis line: `baseline 002-134: stamped 75 DDL, 63 carry data and still run`.

**Aborted at `094_the_engagement_owns_the_refinery_and_the_chain_is_whole.sql`**:
`column "status" is of type fulfillments.fulfillment_status but expression is
of type text`. Root cause: genesis is generated from dev's *current* schema,
so `fulfillments.fulfillments.status` is created as the
`fulfillment_status` enum (added by `168_the_screens_ask_for_columns.sql`)
**before** 094 ever runs. 094's own `INSERT` supplies
`CASE WHEN … THEN 'COMPLETED' ELSE 'PENDING' END` with no cast — fine on dev,
where 094 first ran years before 168 existed and the column was still text,
but fatal on any from-nothing rebuild built at head ≥168. This is genuinely
new: every prior rehearsal measurement in `production-chain.md` either predates
168 or resumed from `chain6` (already past 094), so nothing had run 094
against a post-168 genesis until now. **Production day will hit this exact
abort** unless 094 is fixed before then.

Fix applied locally (uncommitted, per instructions — not committed, not
pushed) at line 138:

```diff
-  CASE WHEN e.shipping_status = 'Delivered' THEN 'COMPLETED' ELSE 'PENDING' END,
+  (CASE WHEN e.shipping_status = 'Delivered' THEN 'COMPLETED' ELSE 'PENDING' END)
+    ::fulfillments.fulfillment_status,
```

Re-ran `migrate`; completed cleanly from 094 through 176. **170 of 170**
migration files now in `exchange.schema_migrations` (matches
`ls api/migrations/*.sql | wc -l`). Zero further aborts.
